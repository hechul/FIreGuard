# 배포 화면과 Pi 시험 연결: 준비 단계

현재 구현은 **연결 및 경로 미리보기 전용**이다. 웹에서 시험 요청을 보내면 Pi가 출발점과 모의 화재에 따른 예상 경로를 계산해 응답한다. 실제 LED 또는 Pi 로컬 시뮬레이션은 제어하지 않는다. 기본적으로 서버 기능과 화면은 비활성화되어 있다.

실제 관제의 `device_state`, `events`와 시험 명령 테이블은 분리된다. 장치 토큰과 다른 운영자 토큰으로 웹 요청을 보호한다. 운영자 키는 브라우저 메모리에만 보관한다. 요청은 30초 뒤 만료되며 Pi는 장치 토큰으로 한 번만 가져간다. 현재 웹에만 있는 N39, N40은 Pi 맵에 없으므로 시험 출발점에서 제외한다.

## 연결 점검을 켜기 전 필요한 설정

1. 별도 테스트 Supabase에서 `supabase/migrations/202611100001_simulation_commands.sql`을 실행하고 RLS 및 RPC 접근 권한을 검증한다. 운영 DB에 아직 적용하지 않았다.
2. 서버에 32자 이상의 `FIREGUARD_SIM_OPERATOR_TOKEN`을 기존 장치 토큰과 서로 다르게 설정한다. 비밀값은 채팅에 공유하지 않는다.
3. `FIREGUARD_SIM_CONTROL_ENABLED=1`을 테스트 배포에만 설정한다. 끄려면 값을 삭제하거나 0으로 변경하고 재배포한다.
4. 친구의 Pi에 `hardware/cloud_sim_bridge.py`를 복사해 `hardware/CLOUD_SIM_BRIDGE_KO.md`대로 드라이런을 실행한다. 드라이런 요청은 실제 장치를 제어하지 않으므로 REAL 클라우드 보고가 없어도 대기열에 등록할 수 있다. Pi가 수신하지 못하면 요청은 만료된다.
5. SIM 화면의 ‘Pi 연결 점검’에서 출발점과 모의 화재를 선택해 요청하고 결과를 확인한다. 수신 점검은 LED를 켜지 않는다.

## 실물 LED 제어 전에 필요한 검증

Pi가 SIM 화면을 사용하는 동안에도 GPIO 센서가 실제 화재를 독립적으로 계속 보고하는지, 실제 화재 발생 시 진행 중인 시험과 Arduino 출력을 어떻게 중단할지, 연결 끊김·명령 만료·재시작·시리얼 포트 충돌 시 안전하게 종료되는지 현장에서 검증해야 한다. 웹에서 보고된 마지막 센서 상태만으로 Pi의 현재 안전을 보장할 수 없다. 실제 하드웨어 확인 전에는 LED 원격 제어를 활성화하지 않는다.

이 문서는 설정 안내이며, SQL 적용·배포·현장 검증이 완료되었다는 의미가 아니다.
