# 벽 부착용 QR 시연

QR은 GPS 대신 부착 위치를 출발점으로 고정한다. 다음 네 위치에만 해당 안내판을 붙인다.

| 위치 | 노드 | 연결 주소 |
|---|---|---|
| 매표소 내부 | N40 | https://fire-guard-seven.vercel.app/mobile/N40 |
| 팝콘 매점 내부 | N19 | https://fire-guard-seven.vercel.app/mobile/N19 |
| 5관 내부 출입구 쪽 | N37 | https://fire-guard-seven.vercel.app/mobile/N37 |
| 동측 복도 분기점 | N33 | https://fire-guard-seven.vercel.app/mobile/N33 |

## 출력과 적용

1. 변경 코드를 배포한 뒤 `/qr`을 연다. 로컬에서 먼저 출력하려면 `static/qr/print.html`을 브라우저로 연다.
2. 인쇄 버튼으로 A4 4장을 인쇄한다. 머리글·바닥글을 끄고 QR 주변 흰 여백을 자르지 않는다.
3. 실제 스마트폰 카메라로 각 QR을 스캔해 위치명과 출발점이 일치하는지 확인한다. 스마트폰은 배포 사이트에 접속할 수 있어야 한다.
4. Pi 모니터가 동작하는 상태에서 N4 단독 화재와 복수 화재를 시연한다. 파란 지도 화살표와 경로 목록이 갱신되는지 확인한다.
5. 인터넷/장비 연결을 끊어 이전 경로가 계속 안내되지 않는지 확인한다. 재연결 후 최신 상태로 복구되는지 확인한다.

## 경로 선택

- 실제 화재 때는 Pi의 `allZone.directedEdges`를 QR 위치부터 따라간다. 별도 서버 최단경로가 실물 LED 안내를 덮지 않는다. 추가 복도 안내와 부분 복도는 독립된 완전 대피경로로 사용하지 않는다.
- 평상시에는 해당 위치의 서버 계산 출구 위치를 보여주고 평상시 안내라고 표시한다. 로컬 SIM 상태는 시뮬레이션이라고 표시한다.
- 지정된 보조 대피지점은 비상구로 부르지 않는다. 경로 없음, 출발 위치 화재, 오래된 보고, 센서 단절, 조회 실패는 구분하여 표시한다.
- 2초 간격으로 읽기 전용 조회한다. 다른 스마트폰의 출발점이나 Pi/관제 화면의 출발점을 변경하지 않는다.
- 이동 중 GPS 추적은 하지 않는다. 다른 QR을 스캔해야 출발 위치가 바뀐다.

## QR 재생성

`python -m pip install -r tools/requirements-qr.txt` 후 `python tools/generate_demo_qr.py`를 실행한다. 위치와 주소 설정은 `qr_locations.py`에 있다. SVG/PNG와 인쇄 HTML은 저장소에 포함되며 웹 서버 실행에는 QR 생성 라이브러리가 필요 없다.
