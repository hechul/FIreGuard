# 실물 LED 경로 현장 점검 기록

사용자가 확인한 경로 누락을 2026-11-12 전달 Pi 코드와 전체 구역 알고리즘으로 재현한 기록이다. 아래 번호는 별도 표시가 없으면 전체 LED의 1부터 시작하는 실물 번호이며, 실제 발광이나 통행 가능성을 검증한 결과가 아니다.

## 확인된 원인

- 5관 N37: E25(N1–N37)와 E33(N2–N1)이 Pi LED 매핑에서 `None`이므로 모든 단일 화재 모의 시험에서 안내가 제외된다. 실제 LED 위치 및 방향은 미확인이다.
- 매표소: 기존 Pi 그래프에는 입구 N14만 있고 내부 노드와 간선이 없었다. 친구의 S10 구간 점검 결과에 위치·개수·방향 `PASS`가 기록돼 있어, 새 REAL 실행에는 N40/E38을 메모리에 추가하고 S10(전체 120~123)을 연결했다. Pi 원본 지도는 변경하지 않는다. 이는 점검 기록과 도면을 활용한 연결이며 실제 발광·방향은 현장에서 다시 확인해야 한다. UI 노드만 추가해서는 Pi 경로와 동기화되지 않는다.
- 완강기 N3: FLM-03 단독 화재에서 빨강은 전체 실물 번호 5~29로 계산되고, N3 자체도 차단된다. N3는 E10(N7–N3)과 E31(N3–N23) 사이의 통로 노드여서 빨강 표시만 축소해도 N7–N23이 자동으로 연결되지는 않는다.
- N2(FLM-02): S14 전체 141~158번이 빨간색으로 계산된다. N4(FLM-04): 107~118 및 124~128, N9(FLM-09): 40~51 및 97~110이 빨간색으로 계산된다. 이 구간 또는 20px 이격 영역과 LED 한 개라도 겹친 간선은 전체 제외돼 과차단이 발생할 수 있다.
- 1관 E13/E20/E16은 S8, 4DX E15는 S4, 화장실 E21/E22는 S5/S6에 이미 매핑돼 있다. 안내 누락이 항상 LED 매핑 누락을 뜻하지 않는다.
- N29는 현재 Pi의 11개 불꽃 센서 위치에 없다. 시뮬레이션 상황인지 새 센서가 설치된 것인지 확인이 필요하다.

## 현장 확인 후 정할 사항

1. 완강기 화재에서 ‘S2 5·6·7번’의 기준이 전체 1-based 번호 5~7인지 S2 구간 내 다섯째~일곱째(전체 9~11)인지, 빨강 영역인지 초록 종료 지점인지 확인한다. 기존 전체 5~7은 N7 앵커 8의 출구 쪽이므로 의미가 달라진다.
2. 5관 내부·출입구 LED의 전체 1-based 번호와 실물 이동 방향을 확인하고, 매표소 내부 S10 120~123이 새 안내 방향과 실제로 일치하는지 시험한다. 전송 슬롯 20부터 +1은 별도이고 중복 적용하지 않는다.
3. 각 화재 시 실제 통행 금지 구간과 빨강 시각화 범위를 별도로 결정하고, 분기점에 맞춰 간선을 분리할 수 있는지 확인한다. 노드·간선 또는 LED 매핑 변경 시 Pi·서버·UI의 그래프/매핑 버전을 함께 갱신한다.
4. 정규 출구가 막힌 상황에서 화장실 등의 보조 목적지는 모형 시연용으로만 표시하고, 실제 공간의 사용 가능성은 별도 확인한다.

`FIREGUARD_PI_PROJECT=/path/to/node1 .venv/bin/python -m unittest discover -s tests -p 'pi_allzone_scenarios_test.py' -v`는 단일 11개와 쌍 55개 화재에 대해 계산·전송 형식 예외를 검사한다. 통과해도 모든 노드에 경로가 있다는 뜻은 아니다.
