# FireGuard 학교 시연 실행 및 점검 가이드

## 준비물

- Raspberry Pi, 연결된 불꽃 센서와 Arduino, LED 전원, 인터넷.
- Vercel에 등록된 **장치 토큰**과 웹 화재 해제에 사용할 **관리자 키**. 서로 다른 값이다. 채팅이나 사진에 노출하지 않는다.
- 아래 명령은 친구의 Raspberry Pi 터미널에서 실행한다. 맥북에서 실행하는 것이 아니다.

## 1. 인터넷과 Arduino 확인

```bash
curl -4 --connect-timeout 5 --max-time 10 https://fire-guard-seven.vercel.app/api/health
```

`"ok":true`가 들어간 결과가 나오면 연결 성공이다. 시간 초과라면 Wi-Fi를 확인하고, 학교망이 막혀 있다면 이전에 성공한 휴대폰 핫스팟을 이용한다. `revision`을 기록하면 배포 버전 확인에 도움이 된다.

```bash
ls -l /dev/serial/by-id/
```

Arduino가 보이고 `ttyACM0`을 가리키는지 확인한다. 다른 번호라면 아래 실행 명령의 포트를 그 번호로 바꾼다.

## 2. 최신 연결 파일 준비

기존 FireGuard 센서·LED 프로그램이 실행 중이면 해당 터미널에서 `Ctrl+C`로 먼저 종료한다. 다른 사람이 실행 중인 프로세스를 임의로 종료하지 않는다.

```bash
git -C ~/FIreGuard pull --ff-only origin main
```

오류 없이 끝나면 다음을 실행한다. 기존 파일은 번호가 붙은 백업으로 남는다.

```bash
cp --backup=numbered ~/FIreGuard/hardware/{real_fire_latch.py,real_pi_service.py,real_device_runtime.py,real_allzone_reporter.py,all_zone_routes.py,real_ticket_overlay.py,real_clear_worker.py,real_flame_reader.py,real_sensor_outbox.py,cloud_sim_led.py,cloud_sim_bridge.py,start_real_monitor.sh} ~/Desktop/node1/hardware/
```

아무 문구가 나오지 않아도 오류가 없으면 복사된 것이다. `git`이 없거나 pull이 실패하면 오류를 보내고 다음 단계로 넘어가지 않는다.

## 3. 실제 센서 + 웹 + 모형 LED 실행

```bash
cd ~/Desktop/node1
```

```bash
bash hardware/start_real_monitor.sh --lab-unverified-led /dev/ttyACM0
```

`Vercel 장치 토큰 입력:`이 나오면 **장치 토큰**을 입력하고 Enter를 누른다. 입력 내용은 보이지 않는 것이 정상이다. 관리자 키를 입력하는 곳이 아니다.

`센서 입력 확인 중...` 다음에 **`클라우드 첫 보고 완료. 이 창을 열어 두세요.`**가 나오면 센서 수집과 첫 서버 보고가 시작된 것이다. LED 점등 및 관리자 해제까지 성공했다는 뜻은 아니므로 아래에서 확인한다. 이 터미널은 계속 켜 둔다. 별도로 옛 `app.py`를 실행할 필요는 없다.

LED가 부드러운 방향 안내로 켜지는 GUIDE 방식은 Arduino에 해당 펌웨어가 설치된 것이 확인된 경우에만 다음 명령을 사용한다. 기존 실행을 Ctrl+C로 종료한 후 실행한다.

```bash
bash hardware/start_real_monitor.sh --lab-guide-led /dev/ttyACM0
```

GUIDE는 약한 초록색 바탕(RGB 0,6,0)에 약한 파란색(RGB 0,0,6)이 출구 방향으로 200ms마다 이동한다. 기존 SEG/GUIDE 지원 펌웨어의 색상 인자를 사용하므로 색 변경만을 위한 Arduino 재업로드는 필요 없다. Pi 코드를 업데이트한 뒤 실행 중인 모니터를 종료하고 위 명령으로 다시 시작해야 적용된다. FLOW 모드는 이 두 색 애니메이션을 사용하지 않는다.

159번이 꺼져 보이면 N4 단독 화재 때 터미널의 `[REAL LED]` 줄에서 `mode=GUIDE`와 `green_slots`의 159~162 포함 여부를 확인한다. 최신 매핑의 N4 GUIDE 명령에는 `SEG 162 161 160 159`가 들어간다. 논리 인덱스는 158, 실제 전송 슬롯은 159이므로 다시 +1 보정하지 않는다. 출구가 없는 복수 화재에서는 5관 구간 전체가 꺼질 수 있다.

명령에는 있지만 실물에서 꺼지는 경우, 다른 LED 제어 프로그램을 종료한 뒤 제공받은 원본 `node1` 디렉터리에서 `python pi_led_usb.py --port /dev/ttyACM0 --raw-test-pixel 159 --seconds 3`으로 슬롯 159만 시험할 수 있다. 이 시험도 꺼져 있으면 실제 번호·배선·픽셀을 확인해야 하며, 임의의 인접 슬롯으로 바꾸지 않는다. 시험 후 위 모니터를 다시 시작한다.

## 4. 실제 동작 시험

1. [배포 대시보드](https://fire-guard-seven.vercel.app/)를 새로 고침하고 REAL 화면에서 Pi 연결과 최근 수신이 갱신되는지 확인한다. 예전 화재 기록은 남아 있을 수 있다.
2. 안전하게 한 센서에만 불꽃을 보여 준다. 웹에 해당 위치가 화재로 표시되고 모형의 빨간 LED와 초록 안내 LED가 켜지는지 확인한다. 실제로 켜진 위치와 웹 표시도 비교한다.
3. 불꽃을 치운 뒤에도 화재 표시가 유지되는지 확인한다.
4. 두 센서를 차례로 감지시켜 두 위치가 함께 유지되고 경로가 변경되는지 확인한다. 불꽃을 모두 치운 뒤 웹의 **실제 화재 수동 해제**에서 관리자 키로 해제한다. 일부만 선택 해제할 수 있다면 나머지는 유지되는지도 확인한다. 감지 중인 센서는 해제되지 않거나 다시 감지될 수 있다.
5. 센서·화재·경로별로 빨간색이 위험 구간에 있고 초록색이 막힌 곳을 통과하지 않는지, 갈림길에서 방향이 이어지는지 확인한다. 웹의 LED 표시는 명령 보고에 기반하며 실제 빛을 직접 검증한 것은 아니다.

## 5. 중점 확인 목록

- 완강기(N3) 화재 시 N7 방향이 과하게 막히는지 확인. S2의 5·6·7이 전체 번호인지 구간 내 번호인지 아직 미확정이다.
- N2 화재 시 매점·5관, N20 화재 시 매표소, N4 화재 시 팝콘 매장·매표소에서 안내가 이어지는지 확인한다.
- N7·N9·N10 및 화장실 화재 시 각 방, 화장실, 완강기 쪽 경로와 끊긴 LED를 확인한다. N29는 현재 확인된 불꽃 센서 번호가 아니라 지도상의 노드다.
- 매표소 내부 LED 120~123과 5관 내부 구간은 실물에서 위치와 방향을 따로 확인한다. 5관 내부 LED 범위는 미확정이다.
- 출구가 막혔을 때 화장실이나 완강기 쪽 대체 경로가 적절히 보이는지 확인한다. 경로가 없는 경우 임의로 정상 출구가 표시되지 않는지도 확인한다.

각 문제는 **감지 센서 번호, 웹 화재 위치, 출발 구역, 예상 방향, 실제 LED가 끊긴 곳**, 사진이나 영상으로 기록한다. 여러 화재면 센서 번호를 모두 적는다.

## 6. 오류가 나면

- `기존 센서·LED·클라우드 프로세스가 실행 중`: 해당 프로그램을 실행한 터미널에서 Ctrl+C로 종료하고 다시 시작한다. 모르면 화면에 나온 목록을 보낸다.
- `GPIO busy`: 센서를 사용하는 기존 프로그램이 있을 수 있다. 오류 전문을 보내고 중복 실행을 피한다.
- `401`: 장치 토큰과 Vercel의 `FIREGUARD_DEVICE_TOKEN`이 일치하는지 확인한다. 비밀값은 보내지 않는다. Vercel 환경변수를 바꿨다면 해당 환경에 저장 후 재배포해야 적용된다.
- Arduino 포트 없음: USB 연결과 `ls -l /dev/serial/by-id/`를 확인한다.
- LED 응답 없음: Arduino 전원·USB·포트·펌웨어와 다른 프로그램의 포트 점유 여부를 확인한다. 웹의 성공 문구만으로 실제 점등을 단정하지 않는다.
- 원인을 모르겠다면 **두 번째 터미널**을 열어 다음 결과와 화면을 보낸다. 토큰은 가리고 보낸다.

```bash
cd ~/Desktop/node1
tail -n 30 runtime/real-service.log runtime/real-sensors.log runtime/real-cloud.log runtime/real-clear.log
```

## 종료와 주의

시연 종료는 실행 중인 터미널에서 `Ctrl+C`를 누른다. 미검증 모형 설정으로 실행하는 것이므로 LED 배선·경로·방향을 실물에서 확인해야 하며, 이 모형을 실제 대피 안전 수단으로 사용하지 않는다.
